# Exaclim interface rules

These constraints record the user’s explicit corrections.

- Use installed library components for controls, cards and notifications. Do not build replacement components.
- No decorative arrows, icon tiles, ornamental illustrations or symbols that resemble actions. An arrow on a control must describe an implemented action, such as opening a select.
- Do not add decorative divider lines, connection badges, placeholder avatars or repeated account-role labels.
- Use normal worksite names. No demonstration site names, slogans, em dashes, middle-dot separators or footer receipt logs.
- Keep the agreed three dashboard areas. Add navigation only when its destination is implemented.
- Keep source labeling at the forecast and actionable stale-data, privacy and emergency states.
- Apply Emil Kowalski’s installed design-engineering guidance within these constraints. Do not add animation or decoration to satisfy a generic design example.
